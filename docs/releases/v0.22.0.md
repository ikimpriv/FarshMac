# FarshMac 0.22.0 — Kubernetes panels and remote workflows

FarshMac is a macOS file manager written in Go, **inspired by Far Manager**. This release brings Kubernetes into the two-panel workflow: browse a cluster, inspect and edit manifests, read logs, and work with files inside containers without leaving the application. FarshMac is an independent project, not an official Far Group release.

## Kubernetes, one panel at a time

Connect through **Commands → Network connections → New Kubernetes cluster…** using a kubeconfig and context. Connection profiles are remembered; credentials stay in your kubeconfig and its authentication providers.

- Browse namespaces, resource types, built-in objects and custom resources. Follow ownership relationships and open pods and containers as folders.
- **F3/F4** view or edit YAML manifests. The editor uses the cluster's OpenAPI schema, including CRDs, to flag unknown fields, invalid types and missing required values. **Ctrl+Space** completes fields and values; **Alt+F2** jumps to the next problem. Saves detect resource-version conflicts.
- **Shift+F3** opens logs, **Alt+F3** follows them, and **Shift+F4** shows describe output. **Ctrl+Q** previews the selected object in the other panel.
- Browse, view, edit and transfer container files. Run a command at the panel prompt inside that container, or open an interactive shell from the Kubernetes menu. The normal local terminal remains available.

The integration uses client-go directly; it does not require an external `kubectl`. Authentication plugins referenced by kubeconfig and shell/file utilities inside a container may still be required.

## Transfers that follow the panels

**F5/F6** use the other panel as the destination. **Shift+F5/Shift+F6** ask for a new name in the current folder or namespace.

Kubernetes panels can apply local YAML/JSON manifests and copy resources between namespaces or clusters. Resource moves create the destination first, then delete the source with UID and resource-version checks. If creation fails, the source is retained; if deletion fails, the error explains that the destination has already been created.

For files, cross-filesystem moves copy before removing the source. Failed or skipped copies retain their source. When both panels address the same pod/container, copies run inside the container and moves use its filesystem rename: file contents are not downloaded to the Mac just to be sent back.

## More responsive, fewer interruptions

- **Cmd+=** opens the same local, remote or Kubernetes location in the other panel; Quick view is left alone. Choosing a volume with **Alt+F1/F2** restores a visible filesystem panel.
- Watcher-confirmed deletions update both Kubernetes panels, including deletion of the last object in a resource-type folder.
- Container filesystem reads no longer run in watcher redraws on the UI thread, fixing stalls when the same pod is open in both panels.
- **Esc/Cancel** cancels Kubernetes requests without waiting for their normal network timeout. Connection failures invalidate cached cluster data.
- Copies within one remote filesystem and editor saves back to their source no longer repeat the generic metadata-limit warning. Actual permission and timestamp failures remain visible.
- Fixed a race between background folder reads and saving connection profiles. YAML indentation, editor navigation, container-tool compatibility and Quick view scrolling also improve in this release.

## Download and install

Download **FarshMac-0.22.0-macOS-universal.zip**, unzip it, and move **FarshMac.app** to Applications. Quit any running copy before replacing it. The universal executable includes Apple Silicon and Intel builds and targets macOS 12 or later.

Verify the download with the accompanying checksum file:

```sh
shasum -a 256 -c FarshMac-0.22.0-macOS-universal.zip.sha256
```

This preview uses the project's **persistent self-signed development certificate**. It is **not Developer ID signed or notarized**. macOS may require per-application approval in System Settings → Privacy & Security. Full Disk Access is a separate permission for protected folders. Signing continuity does not grant that permission automatically.

## Before using it on a cluster

Kubernetes rename/move is **create-then-delete, not an atomic rename**. Owned resources remain orphaned; references in other objects are not automatically rewritten. Namespace rename/move is unsupported, and cluster-scoped resources are not shown. Kubernetes panels are not restored with the window session. Schema checks assist editing but do not replace API-server validation or admission policies.

Archive panels remain read-only. Far Manager binary plugins and macros are not supported. Remote metadata preservation depends on the protocol and server. A universal build does not imply that every feature has been runtime-tested on both architectures and every supported macOS version.

Please report reproducible issues with the FarshMac/macOS versions and non-sensitive examples. Source code is MIT licensed; bundled components and the original Far Manager icon retain their own licenses and attribution.
