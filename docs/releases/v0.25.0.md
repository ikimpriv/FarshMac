FarshMac 0.25.0 makes long searches usable while they run, adds cluster-level Kubernetes browsing and node resource insights, and brings richer selection to the integrated terminal.

FarshMac is an independent macOS project inspired by **Far Manager**. This release remains an early preview.

## Search without waiting for completion

Results appear as they are found. Browse the list, press **F3** to inspect an object, **F2** to stop collecting while keeping the results, or **Enter** to navigate to a match and cancel the remaining search. Kubernetes results can optionally switch to an ownership tree with **F5**; the default flat list stays immediately usable.

Ownership trees retain shared ancestors, deduplicate objects, and remain navigable with deep hierarchies and large result sets. Search and directory traversal use backend-specific strategies with cancellation and explicit boundaries: catalog searches do not descend into pod/container filesystems or nested remote mounts. Hidden subtrees are excluded when hidden-file display is disabled. The initial name mask is selected when opening **Alt+F7**.

## Cluster resources and Node → Pods

**Cmd+Shift+.** switches the active Kubernetes object panel to cluster-level resources and back to its previous location. In filesystem views, including container files, it continues to toggle hidden files.

Built-in resource types retain familiar short names such as `nodes` and `deployments`; colliding extension types use `plural.api-group`. Existing fully qualified built-in paths continue to resolve.

Enter a core Node to open its `pods` folder. The relationship follows `spec.nodeName`, without pretending it is an ownerReference. Listing and watching are filtered on the server, and rows use `namespace:pod` to distinguish identical names across namespaces. F3 and container navigation preserve each pod's original identity.

Pending pods and error states are red; completed and terminating resources are dimmed. Kubernetes panels also support sorting by Age and State.

## Quick Live Metrics for workloads and nodes

**Ctrl+Shift+Q** opens metrics in the opposite panel. Namespace and workload folders aggregate their owned pods. Core Nodes aggregate workload-container CPU and Working set across all namespaces, with separate lines for multiple selected nodes.

For a single node, **Allocatable** defines the chart's upper boundary and quarter divisions. Percentages use Allocatable; the scale expands only when observed usage exceeds it. Redundant Capacity lines and unused rounded-up headroom are removed.

Compact GPU and custom-device bars show scheduler allocation units against allocatable units, with advertised capacity available alongside them. The calculation accounts for init containers and restartable sidecars, and excludes completed pods. These values describe reservations, not hardware utilization; shared GPU slots and MIG resources are not combined into a physical GPU count. DRA-only devices not advertised as extended Node resources are not counted.

Device allocation is collected independently of Metrics Server. CPU and memory usage require Metrics Server and exclude host processes outside pods. Missing metrics for running workloads produce an explicit error rather than a misleading partial total. Unscheduled Pending pods no longer suppress the entire namespace aggregate.

## Terminal and navigation

- Select shell output by character, word, or line boundary using keyboard shortcuts; copy and paste with **Cmd+C/V** while retaining **Ctrl+C** for interrupting commands.
- Drag to select output, use **Option+drag** for rectangular selection, and **Shift+drag** to override mouse-aware terminal applications. Selection also works in loaded disk-backed history pages.
- Recent remote connections form one group, ordered Docker, Kubernetes, then other connections.

## Validation and installation

Regression coverage includes large/deep search results, streaming search cancellation, terminal selection, resource-name collisions, cross-namespace Node → Pods navigation, namespace and node aggregation, device reservations, and Allocatable-based chart scaling. Local checks and race tests passed; the release pipeline reruns checks before signing and packaging.

Download **FarshMac-0.25.0-macOS-universal.zip**, quit FarshMac, unzip, and replace the application. The bundle includes Apple Silicon and Intel executables and targets macOS 12+.

```sh
shasum -a 256 -c FarshMac-0.25.0-macOS-universal.zip.sha256
```

The release uses the existing persistent self-signed identity. It is **not Developer ID signed or notarized**. macOS may require per-app approval under System Settings → Privacy & Security. Full Disk Access is a separate permission; the stable application identity is preserved across this update.
