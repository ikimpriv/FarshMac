FarshMac 0.28.0 introduces **AI Spaces**, an experimental way to organize project files and collaborating console agents inside the familiar two-panel interface.

FarshMac is an independent macOS project inspired by **Far Manager**. This release remains an early preview.

## A project workspace in your panels

Open **Alt+F1 / Alt+F2 → AI Spaces**. Spaces contain Envs, and each Env can provide its agents with a different view of the project.

- **F7** creates a Space or an Env. For a new Env, choose an installed Claude Code or Codex agent and a role: Product, Architect, Coder, Reviewer / Tester, a custom role, or no role.
- **Shift+F6** renames a Space or Env. **F8** removes it without deleting the original project files. Removing an agent entry stops only that agent.
- **F5** from a local filesystem panel attaches files or folders as read/write or read-only references, without copying their contents.
- **Go to real location** opens the backing folder or selects the backing file in a normal filesystem panel.

References are live: writing through a read/write reference changes the real file immediately. Removing an entry from an Env hides or detaches it; it does not delete the original. This preview does not implement the draft's copy-on-write overlay or transactional publication model.

## Agent consoles, roles, and collaboration

Press **Enter** on an agent's virtual executable to start it or return to its existing console. **Cmd+O** returns to the panels while the agent continues working. Each agent receives its Env's MCP connection and private scratch storage.

Role templates supply editable `AGENTS.md` or `CLAUDE.md` instructions. **Options → AI Spaces** manages reusable templates and agent defaults; existing Envs keep their own instruction copies. Additional agents can be added through the Env context menu.

Configure which Envs may communicate and which may direct other agents. Messages, replies, shared file references, and attachments support handoffs between roles. Directing permissions allow configured model/effort choices and explicit fresh-context tasks. CLI changes wait for acknowledgement and fall back to resuming with launch arguments when needed, keeping the console and message queue.

## Review evidence and usage

AI Spaces provides bounded batched reads and edits, isolated workspace commands, immutable review artifacts, and server-recorded test results. Managed Chrome/Chromium checks support reusable scenarios for static web applications, including keyboard interaction, persistence, uploads, downloads, and focused rechecks.

The efficiency report shows transcript-based usage and distinguishes requested settings from observed Codex model/effort. Approval-review usage is accounted for separately. The repository includes test6–test10 experiment reports; their token comparisons are observations, not guaranteed savings or billing estimates.

This release also fixes a shutdown race: an agent is reported finished only after its pending inbox has been saved. Regression coverage exercises delayed writes and preservation of queued tasks.

## Preview requirements and limits

Install and authenticate the supported agent CLIs separately. Browser checks require an installed Chrome/Chromium; project builds need their usual runtimes and dependencies.

AI Spaces uses macOS process sandboxing and Env-scoped MCP access, but it is not a VM or a complete isolation boundary for untrusted code. Network access is not restricted, and source-reference symlink containment and enforced workflow budgets are not implemented. Role instructions guide collaboration; they do not guarantee review quality. Start with trusted projects and agents.

For details, see the [workflow guide](https://github.com/ikimpriv/FarshMac/blob/v0.28.0/docs/AI_SPACES_WORKFLOW.md) and [architecture status](https://github.com/ikimpriv/FarshMac/blob/v0.28.0/docs/AI_SPACES_ARCHITECTURE_DRAFT.md).

## Installation

Download **FarshMac-0.28.0-macOS-universal.zip**, quit FarshMac, unzip, and replace the application. The bundle includes Apple Silicon and Intel executables and targets macOS 12+.

```sh
shasum -a 256 -c FarshMac-0.28.0-macOS-universal.zip.sha256
```

The release pipeline runs Go race tests, vet, renderer and native keyboard checks before signing and packaging. The release reuses the persistent self-signed identity. It is **not Developer ID signed or notarized**; macOS may require approval under System Settings → Privacy & Security. Full Disk Access remains a separate permission.
