# Backlog дореализации FarshMac

## Статус

Все 85 пунктов реализованы на ветке `backlog-fixes` (2026-11-11); решения «docs» из раздела «Решения по расхождениям» внесены в справку F1, README и parity-документы. Задачи из `TODO.md` (проверка прав и ошибки сохранения в редакторе) закрыты пунктами P3-01…P3-04.

Требуют проверки на устройстве (автотесты покрывают только модель):

- P4-09: ⌘-шорткаты в нелатинских раскладках;
- P4-12: минимальный размер окна при шрифте 20–24; доход клавиш размера шрифта (⌘+/⌘−/⌘0) до страницы;
- P4-06: свёрнутое занятое окно при ⌘Q;
- перепривязка zsh precmd при zsh-vi-mode;
- P1-07: подсказка Full Disk Access на реальных защищённых папках;
- обработка символических ссылок на реальном FTP-сервере;
- P3-01: предсказание прав на SMB и read-only томах;
- сохранение тегов Finder после записи в редакторе;
- светлая тема (визуально);
- Cmd+Shift+3/4/5 (перехват системой) и Ctrl+Shift+3/4/5 для закладок;
- cross-volume F6 на реальном втором томе;
- переименование с изменением только регистра на регистрозависимом APFS;
- переподключение при реальном обрыве сети;
- SFTP-сервер без `posix-rename`;
- P5-09: диалог при выходе через ⌘Q и Dock;
- сообщение второго экземпляра приложения;
- размер шрифта в нескольких окнах;
- серые пункты меню в обеих темах.

Отклонения от предложенного в пунктах:

- P5-09: вместо нативного alert — диалог внутри приложения, без `os_log`;
- P1-05: нет отдельного цвета Cyan для ссылок на папки;
- P2-07: нет флажка «больше не показывать»;
- P3-04: другие открытые копии того же файла после сохранения не синхронизируются.

Результат gap analysis по `docs/FUNCTIONAL_SPEC.md`: для каждой функции проверены варианты (тип панели, выделение, ошибки ФС и сети, отмена, занятость, настройки, размер окна, персистентность, мышь и клавиатура) и сверены с кодом. Сюда вошли только случаи, которые код **не обрабатывает или обрабатывает плохо**; каждый подтверждён чтением исходников, ссылки на файлы и функции даны в пунктах. Случаи, которые код обрабатывает, а спецификация не описывала, внесены в приложения `docs/FUNCTIONAL_SPEC.md`.

Задача из `TODO.md` (проверка прав при открытии и сохранении в редакторе) детализирована пунктами P3-01…P3-04; после принятия backlog файл `TODO.md` можно удалить или заменить ссылкой на этот документ.

Приоритеты: P0 — падение, потеря данных или утечка секрета; P1 — функция не работает в реальном сценарии; P2 — неудобство или неконсистентность; P3 — косметика. Оценка: S — до дня, M — несколько дней, L — неделя и больше.

Составлено 2026-11-11 по ветке `main` (коммит `b91313a`).

#### P1-01. Клавиши и операции действуют на невидимые записи (Quick view / Info panel / скрытая панель)
- **Функция и вариант:** Tab, Enter, Ctrl+PgDn, Shift+Enter, Insert/Space, F3–F8, Ctrl+Insert/⌘C, fast find (Alt+символ), Alt+F6, Describe files — когда активная панель находится в режиме `Quick view`, `Info panel` или скрыта (`Hidden`).
- **Текущее поведение:** `Tab` переключает `Active = 1 − Active` без проверки режима и `Hidden` (`app.go:key`). Панель в Quick view/Info сохраняет `Entries` и `Cursor` прежнего файлового режима (`toggleOtherView` не очищает их). `infoPanelKey` перехватывает только стрелки/PgUp/PgDn/Home/End/F3/F4/Ctrl+F12 (`info_panel.go:infoPanelKey`); для Quick view перехвата нет вообще. Далее `enterFile` (`launch.go`), `transferDialog` (`transfers.go`), `deleteSelected` (`delete.go`), `openSystemSelected`, `mark` (`app.go`), `fastFindKey` (`fastfind.go`), `createLink`, `describeFiles` работают через `Panels[Active].Entries/Selected()` без проверки `View`/`Hidden`. Итог: в активной Quick view Enter запускает исполняемый файл под невидимым курсором, F8 предлагает удалить невидимый файл (диалог называет имя, но пользователь не видит контекста), Alt+буква открывает окно `Find` и двигает невидимый курсор, Enter в нём входит в папку и Quick view «уезжает». `volumes()` (`panel_options.go`) делает активной даже скрытую панель. Tree panel в порядке: записи видимы.
- **Требуемое поведение:**
  - Tab пропускает скрытую панель: если `Panels[1−Active].Hidden`, Tab ничего не делает и показывает статус `Other panel is hidden (⌘F1/⌘F2 shows it)`; если обе скрыты, Tab показывает активную (`Hidden = false`). Alt+F1/F2 и `Left/Right → Change volume…` на скрытой панели снимают `Hidden` перед загрузкой.
  - Для активной Quick view/Info panel: Enter, Ctrl+PgDn, Shift+Enter, Insert, Space (при пустой командной строке), F3 (кроме описания в Info), F4 (кроме описания в Info), F5, F6, F7, F8, Delete, Shift+F8, Alt+F6, Ctrl+Insert/⌘C, `Files → Describe files…`, Ctrl+F/Ctrl+; и ⌘Enter игнорируются со статусом `Switch to a file panel first (Tab)`. Alt+символ не открывает fast find. Ctrl+PgUp, Cmd+L, Alt+F12, закладки разрешены (они меняют `Path` источника, что осмысленно для Info panel).
  - Курсор/пометки Quick view/Info панели не меняются; `Hidden` панели не меняется.
  - Мышь: двойной клик по Quick view ничего не делает (сейчас так и есть), но одиночный клик активирует панель, как у Info panel (симметрично).

#### P1-02. Смена источника панели до завершения асинхронной загрузки: откат оставляет панель в несогласованном состоянии
- **Функция и вариант:** ⌘=/⌘Shift+\ (`matchOtherPanel`) на удалённую/архивную папку при таймауте сети; Alt+F1/F2 (`volumes`) из удалённой панели на отмонтированный том; `Network connections → Disconnect active panel` (`disconnectRemote`), когда `RemoteLocalPath` удалён.
- **Текущее поведение:** `matchOtherPanel` (`archive_panel.go`) присваивает `dst.Remote/RemoteLocalPath/Archive` **до** `dst.Load`; при `Async` `Load` всегда возвращает nil (`loadPanel`), поэтому ветка восстановления `dst.Archive = previous` недостижима. `loadPanel` (`panel_load.go`) делает `previous := *p` уже после мутации; при ошибке `pollPanelLoad` восстанавливает `*p = job.previous` → панель с `Remote = src.Remote`, но `Path`/`Entries` локальной папки. Enter по такой записи уходит на сервер. Аналогично `volumes()` ставит `Remote = nil` перед `Load` (панель с `Remote == nil`, но удалёнными `Path`/`Entries`), `disconnectRemote` — то же.
- **Требуемое поведение:** `loadPanel` получает снимок панели от вызывающего (параметр `previous Panel`), либо `matchOtherPanel`/`volumes`/`disconnectRemote` сохраняют `{Remote, RemoteLocalPath, Archive, View, Path}` и регистрируют в `panelLoad` callback отката, который восстанавливает эти поля. Пользователь видит: прежний листинг, в футере текст ошибки (`dial tcp …: i/o timeout`), статус `Other panel kept: <error>` для ⌘=. Для `volumes` на недоступный том: проверка `os.Stat`/`ReadDir(1)` **до** смены источника (как в `goFolderShortcut`), ошибка в статус, панель не трогается. Для `disconnectRemote`: если `RemoteLocalPath` недоступен — `accessibleFolder(local, home)`.

#### P2-01. Назначение — символическая ссылка на каталог (`/tmp`, `~/link`)
- **Функция и вариант:** F5/F6 (local и remote), назначение введено/предложено как путь, последний компонент которого — симлинк на каталог (`/tmp` → `/private/tmp`, пользовательские ссылки).
- **Текущее поведение:** `transfers.go:transferDialog` проверяет назначение через `destination.Lstat(dst)` → симлинк не `IsDir()`. Несколько элементов → `destination must be an existing directory`. Один элемент → `target = dst` → `fsops.transfer`: `os.Lstat(dst)` существует, не каталог → диалог коллизии `The file already exists\n/tmp … Existing: N bytes`; `Overwrite` → staging-копия и `os.Rename(tmp, dst)` **заменяет саму ссылку** файлом (для move — `os.Rename(src, dst)` так же). В `remotefs.Copy.walk` для каталога-источника: `dest.Lstat` → `destination is not a directory`. Тот же код для remote-назначения (`sftpFS.Lstat`).
- **Требуемое поведение:** для определения «назначение — контейнер» использовать `Stat` (следовать ссылке) и в UI, и в `remotefs.Copy.walk` (`create folder`), и в `fsops.transfer` (`di`). Семантика Far Manager: ссылка на каталог ведёт себя как каталог — элементы кладутся внутрь, каталоги сливаются. Ссылка на *файл* остаётся объектом коллизии (как сейчас). `Overwrite` поверх симлинка на каталог не предлагается. В диалоге коллизии для ссылки на файл добавить строку `Existing: symbolic link → <target>`.
- **Граничные случаи:** битая ссылка в назначении (Stat ошибка ENOENT → трактовать как существующий не-каталог, коллизия с `Existing: broken link`); ссылка на каталог внутри источника (проверка `destination is inside source` уже через `EvalSymlinks` — сохранить); remote: `Lstat` на SFTP + `Stat` — нужен метод `Stat` в интерфейсе `remotefs.FS` (FTP: `ReadDir(parent)` не даёт цель ссылки — трактовать симлинк как каталог только если `ReadDir(dst)` успешен).
- **Тесты:** `TestTransferIntoSymlinkedDirectory` (fsops: file→link-to-dir кладёт внутрь, dir→link-to-dir сливается, ссылка цела); `TestCopyDialogAcceptsSymlinkedDirectory` (ui: два отмеченных файла в `/tmp`-подобную ссылку — без ошибки); `TestMoveIntoSymlinkedDirectoryKeepsLink`; `TestCollisionWithFileSymlinkStillAsks`.
- **Приоритет:** P1 (неожиданная замена ссылки, блокировка стандартного `/tmp`).
- **Оценка:** M.

#### P2-02. Cross-volume move: Retry/Skip/метаданные действуют на всё дерево, а не на файл
- **Функция и вариант:** F6, назначение на другом томе (EXDEV), каталог с ошибкой на одном из файлов (нет прав, ENOSPC, исчез) или отказ в диалоге `Cannot preserve metadata` для одного файла.
- **Текущее поведение:** `fsops/transfer.go:moveAcrossVolumes` → `Copy(src, dst, o)` → рекурсивный `copyEntry` **без** `Attempt` на уровне файла. Ошибка любого файла всплывает до `Transfer` → `Attempt("move", <корень>)`; `Retry` повторяет копирование **всего** дерева с нуля (deferred `RemoveAll(dst)` уже удалил частичную копию), `Skip` пропускает **весь** корневой элемент. `Skip` в `metadataQuestions` для одного файла возвращает `ErrSkipped` из `copyEntry` → родительский `copyEntry` удаляет весь каталог → в итоге «Done — 1 item(s) skipped», каталог не перемещён, хотя пользователь ожидал пропуск одного файла. Это противоречит `docs/FILE_OPERATIONS.md` («Retry repeats the failed file or step, not the whole batch») и тексту спеки F6 («Skip → элемент пропущен, источник остаётся»).
- **Требуемое поведение:** cross-volume move выполнять поэлементно, как F5: обойти дерево, для каждого файла `Attempt("move", file, dstFile)` (копия + метаданные + `delete source` файла), каталоги создавать обходчиком, метаданные каталогов применять в обратном порядке, пустой источник-каталог удалять через `Attempt("delete source folder")`; при пропусках источник-каталог остаётся с пропущенными файлами (как у same-volume слияния). Диалог `Error`: `Cannot move\n<file>\nTo: <dstFile>\n\n<err>`. Диалог метаданных — по файлу; `Skip` оставляет только этот файл в источнике, копия файла удаляется. Прогресс: `o.Scan` уже есть — проценты сохраняются.
- **Граничные случаи:** жёсткие ссылки (`hardlinks.go` должен работать поэлементно — `rememberHardlink`/`copyHardlink` уже per-file); отмена между файлами — перемещённые файлы остаются в назначении, в источнике — остальные (как same-volume); `.DS_Store` переносится (`o.moving`); ошибка на `delete source` файла после публикации — Retry только удаления (уже есть семантика `Attempt`).
- **Тесты:** `TestCrossVolumeMoveSkipsSingleFileAndKeepsRest` (один файл без прав на чтение → Skip → остальные перемещены, источник содержит только пропущенный); `TestCrossVolumeMoveRetryRepeatsOnlyFailedFile` (счётчик вызовов `metadataCopier`); `TestCrossVolumeMoveMetadataSkipKeepsOnlyThatFile`.
- **Приоритет:** P1 (повторное копирование гигабайт, потеря прогресса, несоответствие политике).
- **Оценка:** M–L.

#### P2-03. Remote: Retry после обрыва соединения использует мёртвую сессию
- **Функция и вариант:** F5 с участием удалённой панели, F8 remote, F6 remote — сетевой разрыв/таймаут в середине передачи.
- **Текущее поведение:** `remotefs/transfer.go:Copy` открывает `s`, `d` один раз на воркер; `child.Attempt("copy", …, func() { copyFile(s, d, …) })` при `Retry` вызывает `copyFile` на тех же закрытых соединениях → гарантированно та же ошибка; `scan`/`dest` обходчика (`Attempt("read folder")`, `Attempt("create folder")`) — аналогично. `remoteDelete`/`remoteMoveDialog` держат одну `f := config.Dial` на всю операцию. Пользователю остаётся Skip/Cancel.
- **Требуемое поведение:** в `Attempt`-closures удалённых шагов перед повтором переоткрывать сессию: при ошибке, классифицируемой как сетевая (`net.Error`, `io.EOF`, `io.ErrUnexpectedEOF`, `sftp` connection lost, FTP 421/426), воркер закрывает `s`/`d` и вызывает `openTransferEndpoint` заново (с `Attempt("connect")`, который уже есть). Диалог `Error` остаётся прежним; при повторном подключении прогресс-путь показывает `Reconnecting to <label>`. Частичный `.farshmac-part-*` удаляется (уже есть cleanup-сессия 2 с).
- **Граничные случаи:** SFTP с паролем в памяти — reconnect без повторного запроса (пароль хранится в `Config`); unknown host key при reconnect — ошибка, не диалог; FTP: отдельная data-сессия; отмена во время reconnect.
- **Тесты:** `TestRemoteCopyRetryReconnects` (интеграционный с локальным SFTP-сервером: закрыть серверное соединение после первого файла, Retry → второй файл скопирован); `TestRemoteDeleteRetryReconnects`.
- **Приоритет:** P1 (Retry не работает в основном сценарии его применения).
- **Оценка:** M.

#### P2-04. `Skip` на подготовительном шаге (`connect`, `open destination`, `read destination`) завершает операцию как «Done — skipped»
- **Функция и вариант:** F5/F6 с удалённой панелью (или локально при ошибке `Lstat` назначения): ошибка на шаге до начала передачи, ответ `Skip`/`Skip all`.
- **Текущее поведение:** `transfers.go:transferDialog`: `o.Attempt("open destination" …)` → `ErrSkipped` → `return err` → `workProgress` превращает `ErrSkipped` в успех → статус `Done — 1 item(s) skipped`, панели перечитаны, ничего не скопировано. То же для `read destination`, `remotefs/transfer.go:openTransferEndpoint` (`connect`) в обходчике и в воркерах (через `fail(ErrSkipped)` → `first = ErrSkipped`).
- **Требуемое поведение:** для шагов, без которых операция невозможна, не предлагать `Skip`/`Skip all`: диалог `Error` с кнопками `Retry`, `Cancel` (добавить в `fsops.Failure` флаг `Fatal bool`, `operationQuestions` формирует набор кнопок по нему). Если воркер не смог подключиться, а обходчик подключён — предложить `Retry`/`Cancel`, при `Cancel` → `operation cancelled`, при успехе других воркеров — продолжить с меньшим числом воркеров (или просто Cancel, проще).
- **Граничные случаи:** `Skip all` выбран ранее на файловой ошибке (`skipErrors == true`) — на фатальном шаге всё равно показывать диалог; отмена во время `connect` (уже `ctx.Err()`).
- **Тесты:** `TestFatalStepOffersOnlyRetryAndCancel` (ui, подменить `targetEndpoint` ошибкой); `TestConnectSkipDoesNotReportDone`.
- **Приоритет:** P2 (ложный «Done»).
- **Оценка:** S.

#### P2-06. Переименование только регистра (`File` → `file`) на регистронезависимом томе отвергается
- **Функция и вариант:** F6/Shift+F6 локально, то же имя в другом регистре в той же папке (APFS case-insensitive по умолчанию). Также F5 `File` → `file` в ту же папку.
- **Текущее поведение:** `fsops/transfer.go:transfer`: `os.Lstat(dst)` находит тот же inode → `os.SameFile(si, di)` → `source and destination are the same file` → диалог `Move / rename failed`. Для каталога `Folder` → `folder` то же. Теста нет.
- **Требуемое поведение:** в ветке move: если `SameFile(si, di)` и `filepath.Dir(src) == filepath.Dir(dst)` и `strings.EqualFold(Base(src), Base(dst))` и имена различаются — выполнить `os.Rename(src, dst)` напрямую (APFS меняет регистр записи атомарно), `o.CompleteTree(src)`; при `src == dst` (буквально) — прежняя ошибка. Для copy — оставить ошибку, но с текстом `cannot copy a file onto itself`. Для remote move (`remotefs/move.go:moveEntry`) при `Lstat(dst)` существует и имена отличаются только регистром — попробовать `Rename` и только при ошибке сервера показать её (сервер может быть case-sensitive — тогда это обычная коллизия).
- **Граничные случаи:** case-sensitive APFS — `Lstat(dst)` не найдёт, обычный `Move`; жёсткая ссылка с тем же inode в другом имени того же каталога (`a` и `A` — два hardlink) — `EqualFold` истинно, но `Rename` просто заменит `A` ссылкой `a`... нужно сравнить `Nlink > 1` и в этом случае показать коллизию; `..`.
- **Тесты:** `TestMoveCaseOnlyRename` (пропуск, если том case-sensitive — определять через создание `a`/`A`); `TestMoveCaseOnlyRenameDirectory`; `TestCopyOntoItselfMessage`.
- **Приоритет:** P2.
- **Оценка:** S.

#### P2-07. Remote copy с настройками по умолчанию задаёт `Cannot preserve metadata` на каждый файл
- **Функция и вариант:** F5 local↔remote, remote↔remote с включёнными по умолчанию `Preserve permissions`/`Preserve attributes`.
- **Текущее поведение:** `remotefs/transfer.go:portableMetadata` **безусловно** добавляет `remote transfer cannot preserve owner/group and ACL` и `… xattrs, flags and creation time` даже когда `Chmod`/`Chtimes` на SFTP прошли успешно → `MetadataFailure` → диалог на первом файле; без `For all` — на каждом. Для FTP `Chmod` всегда возвращает `FTP does not provide portable permission preservation`. С `workers > 1` первые N воркеров сериализуются на одном и том же вопросе. Спека фиксирует это (расхождение 8), но это UX-дефект: дефолтные настройки делают каждую удалённую копию «вопросительной».
- **Требуемое поведение:** разделить «реальную ошибку» (сбой `Chmod`/`Chtimes`) и «известное ограничение протокола». Ограничение показывать **один раз на операцию** диалогом `Cannot preserve metadata` с текстом `Remote transfers keep only mode and modification time.\nOwner/group, ACL, xattrs, flags and creation time are not transferred.\nContinue for all files?` и кнопками `Continue`, `Cancel` (ответ запоминается на операцию, как `For all`). Реальные ошибки `Chmod`/`Chtimes` — прежний диалог по файлу (Retry/Skip/…). Для FTP при включённом Permissions — один раз `FTP cannot set permissions` аналогично. Опционально: настройка `Settings.RemoteMetadataNotice` «не показывать снова».
- **Граничные случаи:** симлинки (`cannot preserve symbolic-link metadata`) — включить в то же единое уведомление; `For all` из предыдущего диалога должен покрывать и его; `ApplyMetadata` каталогов в конце — не задавать повторно.
- **Тесты:** `TestRemoteCopyAsksMetadataOncePerOperation` (3 файла на SFTP → ровно один диалог); `TestRemoteChmodFailureStillAsksPerFile`.
- **Приоритет:** P2.
- **Оценка:** M.

## Часть 3. Внутренний просмотрщик и редактор

#### P3-01. Предварительная проверка прав при открытии на редактирование (TODO, пункты 1–3)
- **Функция и вариант:** F4 / Alt+F4 / Cmd+Shift+F4 / Shift+F4 (существующий файл) / Alt+F11 (`Edit …`) / F6 (просмотрщик → редактор) для локального файла; F4 для удалённого файла. Варианты: файл без прав на чтение; файл читаем, но ни файл, ни каталог не записываемы; файл записываем, каталог — нет; каталог записываем, файл — нет (0444, чужой владелец); read-only том; `uchg`/`uappnd`; удалённый файл без права записи (по `mode`/владельцу — насколько известно).
- **Текущее поведение:**
  - `document.go: openDocument` делает только `EvalSymlinks` → `os.Open` → `Stat` → `IsRegular`. Без прав на чтение: `open <path>: permission denied` в усечённый статус (в Async — через `openDocumentAsync` → `worker.Status` → `pollTask` → `a.error`, `reportError` не ставится, диалога нет).
  - Права на запись не проверяются ни для файла, ни для каталога. Редактор открывается, пользователь редактирует, и только `fsops.Save` (`os.CreateTemp(filepath.Dir(path))`) сообщает `open <dir>/.farshmac-save-…: permission denied` / `read-only file system` — усечённо.
  - Стратегия сохранения всегда одна — временный файл в том же каталоге + `rename` (`fsops/files.go: Save`). Значит «записываемый файл в незаписываемом каталоге» сохранить **нельзя**, а «0444-файл в записываемом каталоге» — **можно** (молча).
  - `remote_document.go: openRemoteDocument(edit=true)` — никаких проверок `info.Mode()`; ошибка придёт от сервера при сохранении.
  - F6 из просмотрщика (`documentKey`, `key == "F6"`) проверяет только кодировку/бинарность.
- **Требуемое поведение:**
  1. Ввести `fsops.SaveAccess(path) (strategy, err)` (или аналог в `ui`): `strategy ∈ {replace, inplace, none}`. `replace` — каталог записываем (`access(W_OK)` на `Dir(path)`, с учётом read-only тома `statfs`/`MNT_RDONLY`) и файл без `UF_IMMUTABLE`/`SF_IMMUTABLE`/`UF_APPEND`; `inplace` — каталог не записываем, но файл записываем (`access(W_OK)`) и без флагов; `none` — ни то, ни другое. Документ запоминает стратегию (`d.SaveStrategy`), а `saveDocument` использует её (см. P3-03).
  2. Нет прав на чтение (локально): документ не открывается; диалог `Cannot open file` с текстом `<path>\n<reason>` (например `permission denied`), кнопка `OK`. Для F4 добавить подсказку `Check the file permissions or Full Disk Access.`
  3. Читаем, но `strategy == none`: confirm `Read-only file`, текст `<basename> cannot be saved here: <reason>\nOpen it read-only?` (reason: `folder is not writable`, `file is locked (uchg)`, `read-only volume`), кнопки `View`, `Edit anyway`, `Cancel`. `View` → открыть просмотрщиком (как F3); `Edit anyway` → редактор с `ReadOnly = false`, но статус `Saving may fail: <reason>`; `Cancel` → ничего. Диалог показывается из apply-части `openDocumentAsync` (решение пользователя — на engine queue; сама проверка — в worker).
  4. F6 в просмотрщике: та же проверка; при `none` → тот же confirm, но вместо `View` кнопка `Read-only` (переключает в редактор с `ReadOnly = true`, индикатор ` RO`).
  5. Удалённый файл: если `info.Mode()` явно без `w` для всех (`mode&0222 == 0`) → confirm `Remote file is read-only` / `<remotePath> has mode <perm>. Saving will probably fail.` / `View`, `Edit anyway`, `Cancel`. Владельца/группу не угадывать; это только предупреждение.
  6. Архивные документы — без изменений (уже `ReadOnly` + `ArchiveSource`).
  7. Проверка — эвристика: результат не запрещает сохранение, ошибки реального сохранения обрабатываются по P3-02 (TODO, п. 4).
- **Граничные случаи:** символическая ссылка — проверять права разрешённого пути (`resolved`) и его каталога; файл на сетевом томе (SMB) — `access()` может врать, при расхождении положиться на P3-02; Shift+F4 для нового файла — проверять только каталог (`strategy == none` → тот же confirm с `Edit anyway`/`Cancel`, без `View`); Alt+F11 `Edit`-записи — тот же путь (`openDocument(path, true)`); F3 (просмотр) — проверок записи нет; паги > 64 MiB — редактор и так недоступен.
- **Тесты:** `TestEditOpenRefusesUnreadableFileWithDialog` (chmod 0000, Async: ожидается `Dialog.Title == "Cannot open file"`, текст содержит путь); `TestEditOpenWarnsWhenFolderNotWritable` (файл 0644 в каталоге 0555: confirm `Read-only file`, `View` открывает просмотрщик, `Edit anyway` — редактор); `TestEditOpenDetectsInplaceStrategy` (файл 0644, каталог 0555 → `strategy == inplace`, диалога нет); `TestImmutableFileOpensReadOnly` (`chflags uchg` → `none`); `TestRemoteReadOnlyModeWarns` (SFTP-loopback, mode 0444 → confirm). Для каталогов с chmod тесты должны пропускаться под root (`os.Geteuid() == 0`).
- **Приоритет:** P1 (предотвращает ситуацию «правки некуда сохранить»; потери правок как таковой нет благодаря P3-02).
- **Оценка:** M.

#### P3-02. Ошибки открытия/сохранения: читаемое сообщение, сохранение буфера, повтор и Save as (TODO, пункты 4–5)
- **Функция и вариант:** F2 / Cmd+S / Shift+F10 / `Save` в `Save changes` (закрытие, `+`/`-`, Cmd+Q `Save all`) / Shift+F2 Save as; локально и удалённо. Ошибки: `permission denied` (каталог или файл), `read-only file system`, `no space left on device`, `operation not permitted` (`uchg`, sticky), `no such file or directory` (каталог Save as удалён), `link …: file exists` (Shift+F4 — файл успели создать), `file changed on disk; …` / `remote file changed; …` (см. P3-04), ошибки сервера при `Dial`/`Create`/`Rename`, кодирование `text cannot be represented in …`, `editor is read-only`.
- **Текущее поведение:**
  - Буфер и Dirty **сохраняются** во всех ветках: sync — `saveDocument` возвращает ошибку до `markSaved`; Async — клон отбрасывается, `*d = *copy` только в apply (`document_tasks.go: saveDocumentThen`; `task.go: pollTask`). `Saved` печатается только в apply. Т.е. требование «никогда не сообщать об успехе и не терять правки» уже выполняется — кроме одного края: `saveDocument` после успешного `rename` делает `d.Path = path; d.Info, err = os.Stat(path)`; если `Stat` упал, `Path` уже заменён, `Info == nil`, `markSaved` не вызван → следующий F2 пойдёт в `fsops.Create` → `os.Link` → `file exists`.
  - Сообщение об ошибке: только `a.Status`, усечённый до 20–32 символов (`drawDoc`/`tail`). `pollTask` показывает диалог `<label> failed` лишь при `task.reportError` — для `Saving file` / `Saving remote file` / `Opening file` он не ставится. Путь в сообщении теряется первым (усечение слева).
  - Повтор: F2 снова; Save as: Shift+F2 — работает, но пользователю не предлагается.
  - `Save all` при Cmd+Q: первая ошибка прерывает цепочку и отменяет выход, видна только в статусе; какой документ не сохранился — неизвестно (виден лишь текущий экран).
  - Shift+F10 / `Save` в диалоге закрытия: при ошибке документ остаётся (корректно), но причина — в усечённом статусе.
- **Требуемое поведение:**
  1. Любая ошибка сохранения → confirm `Save failed` с текстом `<displayPath>\n<reason>` (две строки; `reason` — `err.Error()` без префикса временного файла: `.farshmac-save-*`/`.farshmac-new-*` заменять на `<folder>`; для `*os.PathError`/`*os.LinkError` печатать `Op` + человекочитаемую причину), кнопки `Retry`, `Save as…`, `Cancel`. `Retry` повторяет ту же операцию (тот же `path`, `overwrite`, `done`); `Save as…` открывает `saveAs()` с тем же `done` (после успешного Save as закрытие/выход продолжаются); `Cancel` — документ остаётся открытым и Dirty, статус `Not saved`.
  2. Для `Save all` (Cmd+Q, закрытие окна): диалог тот же, плюс перед ним документ с ошибкой делается текущим (`selectScreen`), чтобы пользователь видел, что не сохранилось. `Cancel` отменяет выход целиком.
  3. Ошибка открытия (F3/F4/Alt+F11/Shift+F4/удалённое скачивание/архив): confirm `Cannot open file` / `<path>\n<reason>` / `OK` вместо усечённого статуса. Ожидаемые «мягкие» отказы (`Editor limit is 64 MiB…`, `Binary data…`, `Encoding is not lossless…`, `Choose a regular file`) остаются статусами — это не сбои.
  4. Удалённое сохранение: тот же диалог; `Retry` переподключается (новый `Dial`). При ошибке на этапе `Preparing upload` (кодировка/ReadOnly) — статус, как сейчас, без диалога.
  5. Край со `Stat` после `rename`: не менять `d.Path` до успешного `Stat`; при ошибке `Stat` считать сохранение успешным (данные на диске), `markSaved`, а `Info` взять повторным `Lstat` в `Retry` — либо проще: `os.Stat` → ошибка → `d.Info = nil` и статус `Saved (cannot stat file)`; следующее сохранение через `fsops.Create` упадёт с `file exists` — поэтому выбрать первый вариант.
  6. Статус после диалога: `Not saved` (Cancel) / `Saved` (успех после Retry/Save as).
- **Граничные случаи:** `Retry` при `Busy` (другая задача) — диалог не показывать, пока `Busy`; Esc в диалоге = `Cancel`; удалённый документ + `Save as…` — сохраняет локально и очищает `Remote` (текущее поведение, оставить); многократный `Retry` при ENOSPC — ограничений нет; ошибка в `Shift+F10` → после `Cancel` документ не закрывается; `Save all` при ошибке в скрытом документе — переключение экрана на него должно сбросить `TermVisible`.
- **Тесты:** `TestSaveFailureKeepsBufferAndOffersRetry` (каталог 0555 → `Dialog.Title == "Save failed"`, `d.Dirty`, текст содержит путь; chmod 0755 → `Retry` → `Saved`); `TestSaveFailureOffersSaveAs` (кнопка 1 → prompt `Save as` → сохранение в другой путь → `done` вызван); `TestSaveAllStopsOnFailureAndFocusesDocument` (два Dirty документа, у второго каталог 0555 → `a.Doc` = второй, `Quit == false`); `TestAsyncSaveErrorShowsDialogNotTruncatedStatus`; `TestRemoteSaveFailureDialog` (SFTP-loopback с 0555 целевым каталогом); `TestSaveStatFailureDoesNotBreakNextSave`.

#### P3-03. Стратегия сохранения «на месте», когда каталог не записываем
- **Функция и вариант:** F2 / Save as для файла, который записываем сам, но лежит в каталоге без права записи (типично: `/etc/*`-подобные, общие каталоги, каталог другого пользователя с явно выданными правами на файл, каталоги со sticky-bit и чужим владельцем).
- **Текущее поведение:** `fsops/files.go: Save` всегда `os.CreateTemp(filepath.Dir(path), ".farshmac-save-*")` → `permission denied` → сохранить невозможно вообще. Пользователь может только Save as в другое место.
- **Требуемое поведение:**
  1. `fsops.Save` получает стратегию (из P3-01 или вычисляет сама при `EACCES` на `CreateTemp`): если временный файл создать нельзя, а `access(path, W_OK)` проходит — открыть файл `O_WRONLY|O_TRUNC` (**без** `O_CREAT`), записать, `fsync`, закрыть. Перед этим — та же проверка `SameFile/size/mtime`.
  2. Запись на месте не атомарна: перед первым таким сохранением документа — confirm `Save in place` / `<folder> is not writable, so <basename> will be rewritten in place (not atomically). Continue?` / `Save`, `Cancel`. Ответ запоминается на документ (`d.InplaceConfirmed`).
  3. После успеха статус `Saved (in place)`. `Info` обновляется `Stat` (inode тот же).
  4. Если `O_TRUNC` открылся, а запись упала (ENOSPC) — файл усечён; сообщить через P3-02 с текстом `file may be truncated; retry or save elsewhere` и сохранить буфер.
  5. hardlink/xattr/ACL при записи на месте, наоборот, сохраняются — отметить в справке.

Добавить в справку F1 и меню.

Тот же файл дважды: при `showDocument` для локального документа с уже открытым тем же `Path` — не блокировать, но при успешном сохранении обновлять `Info`/`SavedRaw`/`SavedText` **у всех** документов окна с тем же `Path`, если они не Dirty (а Dirty-дубликаты получат диалог п.1 при своём сохранении). #### P4-01. Потерянная интеграционная клавиша: `ShellReady` зависает, stale `panel-command`

#### P4-02. Бесконечный цикл перезапуска shell без backoff
- **Функция и вариант:** Перезапуск shell после выхода; `.zshrc`/`.bash_profile` с `exit`, `exec` несуществующей программы, сломанный `ENV`; shell, падающий сразу после старта.
- **Текущее поведение:** `scheduleShellRestart` ставит `shellRestartAt = now+1s` всегда; `restartShellIfDue` стартует новый shell; он снова выходит → цикл 1 Гц без ограничения (`shell_restart.go`). Каждую секунду создаётся/удаляется `farshmac-shell-*`, в терминал дописывается `[Restarting shell]`, статус мигает `Shell exited; restarting…` ↔ `Shell restarting…`. Пользователю не объясняется причина, выключить цикл нельзя (кроме закрытия окна).
- **Требуемое поведение:**
  1. Считать «быстрым падением» Exit, пришедший менее чем через 5 с после `startTerminalAt` без единого `Ready` (`shellStarted=false`). Задержка: 1 с, 2 с, 4 с, 8 с (экспоненциально), после 5 быстрых падений подряд — перезапуск останавливается: `shellRestartAt` = zero, статус `Shell keeps exiting during startup (5 attempts). Check your shell startup files; press Enter in the terminal or ⌘O to retry`, футер в терминале `⌘O  Panels    ·    Shell stopped: <причина>    ·    Enter: retry`.
  2. В состоянии «остановлен» `input` с `\r`/`\n`, `execute` (панельный Enter) и `showTerminal` вызывают одну попытку перезапуска (сброс счётчика). `execute` при `Term == nil` показывает `Shell unavailable; retrying…` и инициирует перезапуск вместо тихого отказа.
  3. Успешный `Ready` сбрасывает счётчик.
  4. В терминал при остановке вывести одну строку `[Shell exited <N> times during startup; press Enter to retry]`.
- **Граничные случаи:** `exit` набранный пользователем в работающем shell (был `Ready`) — по-прежнему 1 с; `a.Quit`/`closed` — без перезапуска; смена `Settings.Shell` в Terminal settings сбрасывает счётчик (новая конфигурация).
- **Тесты:** Go ui `TestShellRestartBackoffStopsAfterRepeatedStartupFailures` (ZDOTDIR с `.zshrc` = `exit 1`; проверить задержки через `shellRestartAt`, остановку после 5 попыток, статус, перезапуск по Enter); расширить `TestShellRestartDeletedDirectoryAndShutdown`.
- **Приоритет:** P1
- **Оценка:** M

#### P4-03. Ошибка первого старта shell не повторяется; перезапуск с недоступным cwd зацикливается

- **Функция и вариант:** ⌘O/Ctrl+O, ⌘., ⌘C/⌘V/⌘A в терминале; ⌘O, ⌘U, ⌘L, ⌘R, ⌘E/X/Y, Ctrl+F, Ctrl+; в панелях — при активной русской/другой не-латинской раскладке.
- **Текущее поведение:** renderer: `toggle(e)` → `e.key.toLowerCase()==='o'`, остальные — `e.key` (`app.js:attachCustomKeyEventHandler`, `keydown` capture); только ⌘⇧H и ⌘⇧. имеют `e.code`/keyCode-fallback (`app.js`, `window_darwin.m:performKeyEquivalent`). Go `key()` сравнивает `m.Key` (`strings.EqualFold(m.Key,"o")`, `far_keys.go` по `k`), `m.Code` используется только для Alt-акселераторов форм/диалогов и Numpad. Если WebKit при Cmd+клавише в кириллической раскладке отдаёт `e.key = 'щ'` (а не `o`), ⌘O в терминале не перехватывается (`return !e.metaKey` → уходит в нативный слой, где ⌘O не привязан → ничего), в панелях Go получает `Key:"щ"` и не распознаёт. Нативные пункты меню (⌘N/W/Q/C/V/A/M) работают всегда (AppKit сопоставляет key equivalents по латинской раскладке). Тесты (`input.cjs`, `panel_keys.m`) покрывают только латиницу.
- **Требуемое поведение:** для всех ⌘/Ctrl-комбинаций с буквами сравнивать `e.code` (`KeyO`, `KeyC`, …) с fallback на `e.key`; в Go — при `m.Meta||m.Ctrl` и `len(Code)==4 && HasPrefix(Code,"Key")` подставлять латинскую букву из `Code` (как уже сделано для Alt в формах). Документировать в README.
- **Граничные случаи:** раскладки Dvorak/Colemak — `e.code` физический, `e.key` логический; для них нужен `e.key` (латиница) — поэтому порядок: если `e.key` — латинская буква, использовать её; иначе `e.code`. Caps Lock — `toLowerCase`.
- **Тесты:** `input.cjs`: событие `{metaKey:true,key:'щ',code:'KeyO'}` → `key` с `Key:'o'`; Go `TestMetaShortcutsMapCodeForNonLatinKey`.
- **Приоритет:** P2
- **Оценка:** S

#### P4-10. Оверлей истории команд shell: глотает ⌘O, зависает в `Loading…` после перезапуска shell или ошибки запроса

#### P4-12. Минимальный размер окна не согласован с нижней границей 60×15 при крупном шрифте

Либо (дешевле) снизить нижние границы до 40×10 на обоих концах (`Draw` должен выдерживать 40 колонок — проверить `panelColumns`/`key bar`).

#### P4-13. Команда из одних пробелов выполняется и попадает в историю; слишком длинная команда даёт вводящее в заблуждение сообщение

- **Тесты:** Go ui `TestWhitespaceCommandIsNotExecuted`; terminal `TestRequestErrorMessages`.

#### P5-03. Смена host key (MITM) показывается как обрезанная сырая ошибка
- **Функция и вариант:** `connectRemote` к хосту, чей ключ в known_hosts не совпадает с полученным (или помечен `@revoked`).
- **Текущее поведение:** `HostKeyCallback` корректно **не принимает** ключ (возвращает `knownhosts.KeyError` с непустым `Want` / `RevokedError`), но `connectRemote` отдаёт её в `a.error` → строка статуса вида `ssh: handshake failed: knownhosts: key mismatch`, обрезанная по ширине, без fingerprint, без указания файла/строки, без объяснения опасности. Нет теста на UI-уровне (только `TestHostKeysAndSecrets` на уровне `remotefs`).
- **Требуемое поведение:** `connectRemote` распознаёт `*knownhosts.KeyError` с `len(Want) > 0` и `*knownhosts.RevokedError` и показывает confirm `SSH host key changed` с текстом:
  `WARNING: the host key of <host> does not match <file>:<line>.\nReceived: <SHA256:…> (<type>)\nExpected: <SHA256:…>\nThis may be a man-in-the-middle attack. The connection was refused.` Кнопки: только `OK` (никакого «Trust anyway»). Для revoked — заголовок `SSH host key revoked`. Статус после закрытия: `Connection refused: host key mismatch`.
- **Граничные случаи:** несколько записей `Want` (перечислить все); hashed-hosts (fingerprint берётся из `Want[i].Key`); ошибка пришла через `Trust once`-путь (`FixedHostKey` → `ssh: host key mismatch`) — тот же диалог.
- **Тесты:** `TestRemoteHostKeyMismatchShowsWarningDialog` (`testnet.SFTP` + known_hosts с другим ключом → `Form.Title == "SSH host key changed"`, в `Choice` нет кнопки доверия, `Panels[0].Remote == nil`); `TestRemoteRevokedHostKeyRefused`.
- **Приоритет:** P1 (безопасность: пользователь не понимает, что произошло, и будет пробовать «починить» подключение).
- **Оценка:** M.

#### P5-04. Повреждённый setup.json молча заменяется defaults и затем перезаписывается
- **Функция и вариант:** `LoadSetup` при невалидном JSON, при несоответствии типов (`"FontSize": "14"`, `"Shortcuts"` длиной > 10), при отсутствии прав на чтение; затем `Save setup`, `AutoSave`, или любой `saveSetup()` из user menu / associations / folder shortcuts.
- **Текущее поведение:** `readConfigFile` с ошибкой (кроме `IsNotExist`) → `return` без сообщения; `json.Unmarshal != nil` → `return` (частично разобранные данные отбрасываются, хотя `UnmarshalTypeError` допускает продолжение). Пользователь видит заводские настройки без объяснения; первый же `saveSetup()` (например, сохранение folder shortcut `Ctrl+Shift+1`) перезаписывает файл → потеря `UserMenu`, `Associations`, `Shortcuts*`, `MaskGroups`, историй.
- **Требуемое поведение:**
  1. Ошибка чтения (права) → статус `Cannot read setup.json: <err>; using defaults, Save setup is disabled` и флаг `a.setupReadOnly`; `saveSetup` при флаге показывает confirm `Save setup` / `setup.json could not be read at startup. Overwrite it with current settings?` кнопки `Overwrite`/`Cancel`.
  2. Ошибка JSON → файл переименовывается в `setup.json.broken-<YYYYMMDD-HHMMSS>` (не удаляется), статус `setup.json is damaged; saved as setup.json.broken-…, defaults loaded`; для `*json.UnmarshalTypeError` — продолжать с частично разобранной структурой и сообщать `setup.json: <field> has wrong type; default used`.
  3. Те же правила для `session.json` вне этого раздела.
- **Граничные случаи:** пустой файл (0 байт) — считать отсутствующим, без переименования; fallback-файл из `Far Go/` повреждён — переименовывать нельзя (старый каталог не трогаем) → только статус; два окна стартуют одновременно (переименование под `profilesMu`-подобным мьютексом `setupMu`).
- **Тесты:** `TestCorruptSetupIsPreservedAndReported` (пишем мусор, `LoadSetup`, проверяем `.broken-*` и статус, затем `saveSetup` создаёт новый файл); `TestSetupTypeErrorKeepsPartialSettings` (`"FontSize":"x"` → остальные поля загружены); `TestUnreadableSetupBlocksSilentOverwrite` (chmod 000, `saveSetup` → confirm, не запись).

- **Оценка:** M.

#### P5-05. Ошибки подключения видны только в обрезанной строке статуса
- **Функция и вариант:** `connectRemote`: таймаут (15 с), отказ в аутентификации, `no usable SSH identity…` с длинным hint, ошибка известных хостов, `cannot read SSH private key …`, FTP `530 Login incorrect`, TLS-ошибка FTPS. Также профиль, указывающий на недоступный хост.

#### P5-06. Нет keyboard-interactive аутентификации по паролю
- **Функция и вариант:** SFTP к серверу с `PasswordAuthentication no` + `KbdInteractiveAuthentication yes` (типично для macOS Remote Login, FreeBSD, многих hardened-конфигов и 2FA).

- **Тесты:** `TestSFTPKeyboardInteractivePassword` в `remotefs` (тестовый ssh-сервер с `KeyboardInteractiveCallback`, без `PasswordCallback` → подключение успешно); `TestKeyboardInteractiveRefusesEchoPrompt`.

- **Функция и вариант:** `ftps://` к серверу с self-signed сертификатом; `ftp://` (пароль в открытом виде).
- **Текущее поведение:** FTPS: `tls.Config` без `InsecureSkipVerify`, системные корни → `x509: certificate signed by unknown authority` в статусе (корректно, тест `TestExplicitFTPSProtectsDataConnection`), но без аналога `Trust once` по отпечатку сертификата. FTP: пароль уходит открытым текстом без какого-либо предупреждения, в т.ч. при выборе профиля.
- **Требуемое поведение:** FTPS: `VerifyPeerCertificate` → при ошибке цепочки возвращать `*remotefs.UnknownCertificate{Host, Fingerprint, Raw}`; `connectRemote` показывает confirm `Unknown FTPS certificate` / `<host> SHA256:<fp>\n<Subject>, valid until <date>. Trust for this connection?` (`Trust once`/`Cancel`); доверие — pin по raw-отпечатку в `Config.CertFingerprint` (`json:"-"`), не `InsecureSkipVerify`. FTP: первый раз для профиля — confirm `Plain FTP` / `Passwords and files are sent unencrypted. Continue?` (`Continue`/`Cancel`) с `Remember choice`.
- **Тесты:** `TestFTPSSelfSignedAsksForTrust` (на базе `ftps_test.go`); `TestPlainFTPWarnsOnce`.
- **Приоритет:** P3.
- **Оценка:** M.

#### P5-22. Строка статуса: перезапись и обрезка сообщений
- **Функция и вариант:** `Setup saved`/`Connected: …`/ошибка подключения появляются в момент, когда shell заканчивает старт или команду → `Poll` ставит `Exit N · ⌘O panels / terminal` даже в режиме панелей и стирает сообщение; длинные ошибки (`no usable SSH identity…; id_rsa: …; id_ecdsa: …`) обрезаются без признака обрезки; нет способа прочитать прошлое сообщение.
- **Текущее поведение:** `app.go:Poll` (`e.Ready`), `draw.go:Draw` (`g.Text(... g.W)`), `task.go:pollTask`.
- **Требуемое поведение:** событие `Ready` shell обновляет статус только если `TermVisible` или текущий статус пустой / является предыдущим shell-статусом (хранить `a.shellStatus`); при обрезке — добавлять `…` в последнюю колонку; `Ctrl+Shift+S`? нет — добавить пункт `Commands → Last message` / клик по строке статуса, открывающий confirm `Message` с полным текстом; `a.error` хранит последние 20 сообщений (`a.messages`) для этого окна.
- **Тесты:** `TestShellReadyDoesNotOverwritePanelStatus`; `TestLongStatusIsTruncatedWithEllipsis`; `TestStatusClickShowsFullMessage`.
- **Приоритет:** P3.
- **Оценка:** S.

#### P5-23. Dialog (prompt): нет курсора, Delete и вставки в середину
- **Функция и вариант:** все однострочные промпты (`Make folder`, `Change directory`, `Select group`, `Remote move / rename`, `Tree settings` …): `ArrowLeft/Right/Home/End` только снимают выделение, курсор всегда в конце; `Delete` не обрабатывается; вставка только в конец; редактирование длинного пути (`Remote move / rename` с готовым значением) требует стирать хвост.
- **Текущее поведение:** `app.go:key` (ветка `a.Dialog != nil`), `draw.go:drawDialog` (`cursor = len(Input)`).
- **Требуемое поведение:** перевести `Dialog` на движок `Form` с одним полем (`a.prompt` → `a.form` с `Primary="OK"`), что даёт курсор, `Delete`, вставку в позицию, `⌘A`, мнемоники; сохранить `RememberDialogValues`/`SelectDialogInput`, визуальные фикстуры (`TestDialogVisualFixtures`) обновить. Либо минимально: добавить `Cursor` в `Dialog` и обработку `ArrowLeft/Right/Home/End/Delete`, вставку по курсору.
- **Тесты:** `TestPromptCursorEditing` (Home → ввод → вставка в начало; Delete).
- **Приоритет:** P3.
- **Оценка:** M (перевод на Form) / S (минимальный вариант).
